# 1장: 기초 개념

## 1.1 운영체제의 역할과 구조

### 운영체제란?
운영체제(OS)는 하드웨어와 응용 프로그램 사이에서 중재자 역할을 하는 시스템 소프트웨어입니다.

### 주요 역할
```
┌─────────────────────────────────────────────┐
│              응용 프로그램                    │
│         (게임, 웹브라우저, 등)                │
├─────────────────────────────────────────────┤
│              Win32 API                       │
│      (CreateProcess, ReadFile, 등)           │
├─────────────────────────────────────────────┤
│              운영체제 커널                    │
│    (프로세스 관리, 메모리 관리, I/O 등)       │
├─────────────────────────────────────────────┤
│              하드웨어                        │
│       (CPU, RAM, 디스크, 네트워크)           │
└─────────────────────────────────────────────┘
```

#### 1. 프로세스/스레드 관리
- 프로그램 실행 및 종료
- CPU 시간 할당 (스케줄링)
- 멀티태스킹 지원

#### 2. 메모리 관리
- 가상 메모리 시스템
- 메모리 할당 및 해제
- 메모리 보호

#### 3. 파일 시스템
- 파일 읽기/쓰기
- 디렉토리 관리
- 접근 권한 제어

#### 4. I/O 관리
- 디바이스 드라이버
- 입출력 버퍼링
- 인터럽트 처리

#### 5. 보안
- 사용자 인증
- 접근 제어
- 암호화

## 1.2 커널 모드 vs 유저 모드

Windows는 **두 가지 실행 모드**를 사용하여 시스템을 보호합니다.

### 개념도
```
┌───────────────────────────────────────────────────────────┐
│                      유저 모드 (Ring 3)                    │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐      │
│  │ 게임.exe │  │브라우저 │  │ Word    │  │ 내앱.exe│      │
│  └────┬────┘  └────┬────┘  └────┬────┘  └────┬────┘      │
│       │            │            │            │            │
│       └────────────┴─────┬──────┴────────────┘            │
│                          │                                │
│                    Win32 API                              │
│              (kernel32.dll, user32.dll)                   │
├──────────────────────────┼────────────────────────────────┤
│                    시스템 콜                              │
│                     (SYSCALL)                             │
├──────────────────────────┼────────────────────────────────┤
│                      커널 모드 (Ring 0)                    │
│                          │                                │
│              ┌───────────┴───────────┐                    │
│              │     ntoskrnl.exe      │                    │
│              │    (NT 커널 핵심)      │                    │
│              └───────────┬───────────┘                    │
│                          │                                │
│    ┌─────────┬───────────┼───────────┬─────────┐         │
│    │         │           │           │         │         │
│  ┌─┴──┐  ┌──┴──┐   ┌───┴───┐   ┌──┴──┐  ┌──┴──┐        │
│  │ HAL│  │ I/O │   │Memory │   │Proc │  │ FS  │        │
│  └────┘  │ Mgr │   │  Mgr  │   │ Mgr │  │     │        │
│          └─────┘   └───────┘   └─────┘  └─────┘        │
└───────────────────────────────────────────────────────────┘
```

### 유저 모드 (User Mode)
- **Ring 3** 권한 수준
- 일반 응용 프로그램이 실행되는 영역
- **제한된 권한**: 하드웨어 직접 접근 불가
- 보호된 메모리 공간
- 문제 발생 시 해당 프로세스만 종료

```c
// 유저 모드 코드 예시
int main() {
    // 직접 하드웨어 접근 불가
    // 반드시 Win32 API를 통해야 함
    HANDLE hFile = CreateFile(L"test.txt", ...);  // API 호출
    return 0;
}
```

### 커널 모드 (Kernel Mode)
- **Ring 0** 권한 수준
- OS 핵심 코드, 드라이버가 실행
- **완전한 권한**: 모든 하드웨어 접근 가능
- 모든 메모리 접근 가능
- 문제 발생 시 **블루스크린(BSOD)**

### 모드 전환
```
유저 모드 코드                    커널 모드 코드
      │                               │
      │ CreateFile() 호출             │
      │──────────────────────────────>│
      │      [시스템 콜 발생]           │
      │                               │
      │                         NtCreateFile() 실행
      │                               │
      │<──────────────────────────────│
      │      [결과 반환]               │
      │                               │
```

### 왜 분리하는가?
1. **안정성**: 응용 프로그램 버그가 시스템을 망가뜨리지 않음
2. **보안**: 악성 코드가 시스템 핵심에 접근 불가
3. **격리**: 프로세스 간 메모리 보호

## 1.3 Windows 아키텍처 개요

### NT 커널 구조
```
┌─────────────────────────────────────────────────────────────────┐
│                         유저 모드                                │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │                    서브시스템 DLL                          │   │
│  │  ┌─────────────┐ ┌─────────────┐ ┌─────────────────────┐ │   │
│  │  │ kernel32.dll│ │ user32.dll  │ │    advapi32.dll     │ │   │
│  │  └─────────────┘ └─────────────┘ └─────────────────────┘ │   │
│  └──────────────────────────────────────────────────────────┘   │
│                              │                                   │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │                     ntdll.dll                             │   │
│  │            (시스템 콜 스텁, 런타임 라이브러리)              │   │
│  └──────────────────────────────────────────────────────────┘   │
├─────────────────────────────────────────────────────────────────┤
│                         커널 모드                                │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │                    Executive                              │   │
│  │  ┌─────────┐ ┌──────────┐ ┌────────┐ ┌────────────────┐  │   │
│  │  │ I/O Mgr │ │Memory Mgr│ │ Ob Mgr │ │ Process Mgr    │  │   │
│  │  └─────────┘ └──────────┘ └────────┘ └────────────────┘  │   │
│  │  ┌─────────┐ ┌──────────┐ ┌────────┐ ┌────────────────┐  │   │
│  │  │ Sec Mgr │ │ Cache Mgr│ │ PnP Mgr│ │ Power Mgr      │  │   │
│  │  └─────────┘ └──────────┘ └────────┘ └────────────────┘  │   │
│  └──────────────────────────────────────────────────────────┘   │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │                      커널 (Kernel)                        │   │
│  │         스케줄링, 인터럽트 처리, 동기화 기본요소            │   │
│  └──────────────────────────────────────────────────────────┘   │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │            HAL (Hardware Abstraction Layer)               │   │
│  │              하드웨어 추상화, 인터럽트 컨트롤러             │   │
│  └──────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────┘
                              │
                    ┌─────────┴─────────┐
                    │     하드웨어       │
                    └───────────────────┘
```

### 주요 구성 요소

#### 1. HAL (Hardware Abstraction Layer)
- 하드웨어 차이를 추상화
- 커널이 특정 하드웨어에 종속되지 않게 함
- 인터럽트 컨트롤러, 타이머, DMA 처리

#### 2. 커널 (Kernel)
- **ntoskrnl.exe**의 하위 계층
- 스레드 스케줄링
- 인터럽트/예외 디스패칭
- 동기화 기본 요소 (spinlock 등)

#### 3. Executive
- 다양한 관리자(Manager)들의 집합:

| 관리자 | 역할 |
|--------|------|
| I/O Manager | 파일 시스템, 디바이스 드라이버 관리 |
| Memory Manager | 가상 메모리, 페이징 |
| Object Manager | 커널 객체 관리 (핸들 테이블) |
| Process Manager | 프로세스/스레드 생성 및 종료 |
| Security Reference Monitor | 접근 권한 검사 |
| Cache Manager | 파일 시스템 캐시 |
| PnP Manager | Plug and Play 디바이스 |
| Power Manager | 전원 관리 |

#### 4. 서브시스템 DLL
- Win32 API의 실제 구현
- 유저 모드에서 동작
- 시스템 콜을 통해 커널과 통신

### 주요 시스템 파일

| 파일 | 역할 |
|------|------|
| ntoskrnl.exe | NT 커널 + Executive |
| hal.dll | Hardware Abstraction Layer |
| ntdll.dll | 시스템 콜 스텁, 유저모드 런타임 |
| kernel32.dll | 핵심 Win32 API |
| kernelbase.dll | kernel32의 기본 기능 |
| user32.dll | 윈도우, 메시지, UI |
| gdi32.dll | 그래픽 장치 인터페이스 |
| advapi32.dll | 보안, 레지스트리, 서비스 |

## 1.4 Win32 API 소개

### Win32 API란?
Windows 운영체제가 제공하는 **C 언어 기반 인터페이스**입니다.

### API 호출 흐름
```
응용 프로그램
      │
      │ CreateFile("test.txt")
      ▼
kernel32.dll
      │
      │ CreateFileW() → CreateFileInternal()
      ▼
kernelbase.dll
      │
      │ NtCreateFile 준비
      ▼
ntdll.dll
      │
      │ SYSCALL 명령어 실행
      ▼
─────────────────────────── 유저/커널 경계 ───────────────────────
      │
      ▼
ntoskrnl.exe
      │
      │ NtCreateFile() 실행
      │ → I/O Manager
      │ → File System Driver
      ▼
결과 반환
```

### 주요 API 카테고리

#### 1. 프로세스/스레드 (kernel32.dll)
```c
CreateProcess()      // 프로세스 생성
ExitProcess()        // 프로세스 종료
CreateThread()       // 스레드 생성
ExitThread()         // 스레드 종료
GetCurrentProcess()  // 현재 프로세스 핸들
GetCurrentThread()   // 현재 스레드 핸들
```

#### 2. 메모리 (kernel32.dll)
```c
VirtualAlloc()       // 가상 메모리 할당
VirtualFree()        // 가상 메모리 해제
HeapAlloc()          // 힙 메모리 할당
HeapFree()           // 힙 메모리 해제
```

#### 3. 파일 I/O (kernel32.dll)
```c
CreateFile()         // 파일 열기/생성
ReadFile()           // 파일 읽기
WriteFile()          // 파일 쓰기
CloseHandle()        // 핸들 닫기
```

#### 4. 동기화 (kernel32.dll)
```c
CreateMutex()        // 뮤텍스 생성
CreateEvent()        // 이벤트 생성
CreateSemaphore()    // 세마포어 생성
WaitForSingleObject()// 대기
```

#### 5. 네트워크 (ws2_32.dll)
```c
socket()             // 소켓 생성
bind()               // 주소 바인딩
listen()             // 연결 대기
accept()             // 연결 수락
send() / recv()      // 데이터 송수신
```

### 명명 규칙

#### 헝가리안 표기법
```c
DWORD  dwSize;       // dw = DWORD (32비트 부호 없는 정수)
HANDLE hFile;        // h  = Handle
LPSTR  lpBuffer;     // lp = Long Pointer
BOOL   bSuccess;     // b  = Boolean
UINT   nCount;       // n  = Number (정수)
TCHAR  szName[256];  // sz = String Zero-terminated
LPWSTR pwszPath;     // pwsz = Pointer to Wide String Zero-terminated
```

#### 함수 접미사
```c
CreateFileA()        // A = ANSI (char*)
CreateFileW()        // W = Wide (wchar_t*)
CreateFile()         // 매크로: UNICODE 정의에 따라 A 또는 W

// Ex = Extended (확장 버전)
CreateProcessExW()
```

### 데이터 타입

| 타입 | 크기 | 설명 |
|------|------|------|
| BYTE | 1바이트 | unsigned char |
| WORD | 2바이트 | unsigned short |
| DWORD | 4바이트 | unsigned long |
| QWORD | 8바이트 | unsigned __int64 |
| BOOL | 4바이트 | int (TRUE/FALSE) |
| HANDLE | 포인터 크기 | 커널 객체 핸들 |
| LPVOID | 포인터 크기 | void* |
| LPCWSTR | 포인터 크기 | const wchar_t* |

### 에러 처리
```c
HANDLE hFile = CreateFile(...);
if (hFile == INVALID_HANDLE_VALUE) {
    DWORD dwError = GetLastError();  // 마지막 에러 코드 획득

    // 에러 메시지 얻기
    LPWSTR pMessage = NULL;
    FormatMessageW(
        FORMAT_MESSAGE_ALLOCATE_BUFFER | FORMAT_MESSAGE_FROM_SYSTEM,
        NULL,
        dwError,
        0,
        (LPWSTR)&pMessage,
        0,
        NULL
    );

    wprintf(L"Error %d: %s\n", dwError, pMessage);
    LocalFree(pMessage);
}
```

### 자주 쓰는 에러 코드
| 코드 | 이름 | 의미 |
|------|------|------|
| 0 | ERROR_SUCCESS | 성공 |
| 2 | ERROR_FILE_NOT_FOUND | 파일 없음 |
| 5 | ERROR_ACCESS_DENIED | 접근 거부 |
| 6 | ERROR_INVALID_HANDLE | 잘못된 핸들 |
| 87 | ERROR_INVALID_PARAMETER | 잘못된 매개변수 |
| 997 | ERROR_IO_PENDING | 비동기 I/O 진행 중 |

## 1.5 핸들과 커널 객체

### 커널 객체란?
운영체제가 관리하는 리소스를 나타내는 데이터 구조입니다.

```
┌─────────────────────────────────────────────────────────────┐
│                        커널 모드                             │
│   ┌─────────────────────────────────────────────────────┐   │
│   │              커널 객체 테이블                         │   │
│   │  ┌───────┬───────────────────────────────────────┐  │   │
│   │  │ 인덱스 │           커널 객체                    │  │   │
│   │  ├───────┼───────────────────────────────────────┤  │   │
│   │  │   1   │ Process Object (게임.exe)              │  │   │
│   │  │   2   │ Thread Object                         │  │   │
│   │  │   3   │ File Object (data.txt)                │  │   │
│   │  │   4   │ Event Object                          │  │   │
│   │  │  ...  │ ...                                   │  │   │
│   │  └───────┴───────────────────────────────────────┘  │   │
│   └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
                              ▲
                              │ 핸들 = 인덱스
                              │
┌─────────────────────────────────────────────────────────────┐
│                        유저 모드                             │
│   ┌─────────────────────────────────────────────────────┐   │
│   │                    프로세스                          │   │
│   │                                                     │   │
│   │  HANDLE hFile = CreateFile(...)  // hFile = 0x3    │   │
│   │                                                     │   │
│   │  // 핸들을 통해 커널 객체 조작                        │   │
│   │  ReadFile(hFile, ...);                              │   │
│   │  CloseHandle(hFile);                                │   │
│   └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

### 핸들의 특징
1. **프로세스 고유**: 각 프로세스마다 별도의 핸들 테이블
2. **간접 참조**: 실제 메모리 주소가 아닌 인덱스
3. **보안**: 유저 모드에서 커널 객체 직접 접근 불가

### 주요 커널 객체 종류
| 객체 | 용도 | 생성 함수 |
|------|------|-----------|
| Process | 프로세스 | CreateProcess |
| Thread | 스레드 | CreateThread |
| File | 파일/디바이스 | CreateFile |
| Event | 이벤트 동기화 | CreateEvent |
| Mutex | 상호 배제 | CreateMutex |
| Semaphore | 세마포어 | CreateSemaphore |
| Timer | 타이머 | CreateWaitableTimer |
| I/O Completion Port | 비동기 I/O | CreateIoCompletionPort |

### 핸들 사용 규칙
```c
// 1. 핸들 획득
HANDLE hFile = CreateFile(L"test.txt", GENERIC_READ, 0, NULL,
                          OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, NULL);

// 2. 유효성 검사
if (hFile == INVALID_HANDLE_VALUE) {
    // 에러 처리
    return;
}

// 3. 핸들 사용
ReadFile(hFile, buffer, sizeof(buffer), &bytesRead, NULL);

// 4. 반드시 닫기 (리소스 누수 방지!)
CloseHandle(hFile);
```

## 게임서버 관점에서의 1장 핵심 포인트

### IOCP 게임서버 설계 시 알아야 할 것

1. **커널/유저 모드 경계 이해**
   - 시스템 콜은 비용이 있음 → 불필요한 API 호출 최소화
   - IOCP는 커널 모드에서 I/O 완료를 관리

2. **핸들 관리의 중요성**
   - 소켓도 핸들의 일종
   - 핸들 누수 = 서버 장애
   - 수천 클라이언트 = 수천 개의 핸들

3. **Windows 아키텍처 이해**
   - I/O Manager가 IOCP의 핵심
   - 비동기 I/O는 커널에서 완료 통보

```c
// 게임서버의 전형적인 핸들 사용 예
HANDLE hIOCP;           // I/O Completion Port 핸들
SOCKET listenSocket;    // 리슨 소켓 (핸들)
SOCKET clientSockets[MAX_CLIENTS];  // 클라이언트 소켓들

// 모든 핸들은 반드시 정리해야 함
void Cleanup() {
    for (int i = 0; i < clientCount; i++) {
        closesocket(clientSockets[i]);
    }
    closesocket(listenSocket);
    CloseHandle(hIOCP);
}
```

## 정리

| 개념 | 핵심 내용 |
